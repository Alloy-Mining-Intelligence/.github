# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in any Alloy Mining Intelligence repository, please report it
responsibly.

**Do not open a public GitHub issue for security vulnerabilities.**

### How to Report

Use GitHub's private vulnerability reporting on the affected repository — the **Report a vulnerability**
button on that repository's **Security** tab — or email <security@alloymining.ai>.

Private vulnerability reporting is preferred. It keeps the report, the discussion, and the fix in one
place, and it does not expose the issue while a patch is being prepared.

### What to Include

- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix, if you have one

### Response Timeline

| Stage | Target |
|---|---|
| Acknowledgment | Within 48 hours |
| Initial assessment | Within 5 business days |
| Fix or mitigation | Per the severity targets below |

Remediation targets by severity: **Critical 48 hours · High 7 days · Medium 30 days · Low 90 days.**

### Disclosure

We will keep you informed as the report is triaged and fixed, and we will confirm when a fix ships. We
ask that you give us a reasonable opportunity to release a fix before disclosing publicly. We are happy
to credit reporters who would like to be credited.

## Supported Versions

We support the latest released version of each product. Security patches are not backported to older
versions unless explicitly stated.

## Scope

This policy covers the repositories in the [Alloy Mining Intelligence](https://github.com/Alloy-Mining-Intelligence)
organization. It does not cover vulnerabilities in third-party services or dependencies — please report
those to the relevant maintainer, though we are glad to hear about anything reachable through our code.
